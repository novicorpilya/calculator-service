# Технический аудит проекта (HICS Calculator Service)

**Дата**: 10 января 2026 г. **Роль**: Senior Team Lead / Auditor **Статус**:
Подготовка к развертыванию

## 1. Резюме аудита

Проведен глубокий технический аудит кодовой базы. Основное внимание уделено
архитектурной целостности, реализации Optimistic UI, управлению UID на стороне
клиента и общей гигиене кода перед продакшеном.

В ходе аудита были выявлены и исправлены критические ошибки в передаче
метаданных чата, а также проведен рефакторинг механизмов синхронизации. Проект
находится в высокой степени готовности к деплою.

---

## 2. Ключевые архитектурные решения

Проект следует **Feature-Oriented Layered Architecture**:

- **Infrastructure Layer**: Supabase (DB, Auth, Realtime).
- **Repository Layer**: Абстракция доступа к данным (ChatRepository,
  CalculationRepository).
- **Service Layer**: Бизнес-логика и координация (ChatService,
  CalculationService).
- **Domain Layer**: Zod-схемы, сущности и логика расчетов (CalculationEngine).
- **Presentation Layer**: React компоненты с использованием TanStack Query для
  управления состоянием.

## 4. Выявленные и исправленные проблемы (Technical Cleanup)

### 4.1. Удаление Мертвого Кода (Dead Code)

- **Удален** `MessageStore.ts`. Локальное хранилище старого образца полностью
  заменено на кэш TanStack Query.

### 4.2. Безопасность и Типизация

- **Расширен** `MessageEventType`: Добавлены сигналы `READ` и `RECONNECT` для
  корректной типизации синхронизации без использования `as any`.
- **Удалены** небезопасные приведения типов в `BroadcastService` и
  `useUnreadCount`.

### 4.3. Гигиена Логирования (Production Hygiene)

- **PresenceService**: Прямые вызовы `console.warn/error` заменены на системный
  логгер с контекстом.
- **CalculationRepository**: Логирование ошибок RPC переведено на `ILogger`.
- **VoicePlayerContext**: Удалены отладочные логи воспроизведения.

## 5. Рекомендации к следующей итерации

1. **Deduplication (Mixed Logic)**:
   - В компонентах `InventoryManager` и `NewCalculationWizard` используется
     ручной `useEffect` для загрузки справочников (Suppliers, Global Inventory).
   - **Рекомендация**: Вынести эти запросы в хуки `useSuppliers` и
     `useGlobalInventory` на базе React Query для обеспечения глобального
     кэширования и предотвращения дублирующих сетевых запросов.
2. **Performance**:
   - Рассмотреть использование `react-virtual` для очень длинных историй чата
     (более 500 сообщений).
3. **Internal Testing**:
   - Покрыть сложным интеграционным тестом цепочку
     `Optimistic Send -> Server Confirm -> Identity Swap` для гарантированного
     отсутствия регрессий в UX чата.
