# Текущий функционал и анализ платформы HICS

В этом документе описан текущий реализованный функционал для ролей **Клиент** и
**Менеджер**, а также схема статусов и переходов (State Machine).

---

## 👥 Роли и Возможности

### 1. Клиент (Client)

Конечный пользователь, владелец заведения (ресторан, отель, кафе).

- **Дашборд:**
  - Обзор (Stats): Всего проектов, активные, потрачено.
  - Мои расчеты (List): Список всех созданных проектов со статусами.
  - Заведения (Venues): Управление профилями заведений (адрес, фото, юр. лица).
  - Чат (Global Chat): Общение с менеджерами.
- **Работа с расчетом:**
  - **Создание:** Мастер (Wizard) создания расчета (выбор типа, площади, кухни).
  - **Редактирование:** Возможность менять параметры в статусах `Черновик`
    (Draft) и `Правки` (Changes).
  - **Отправка:** Отправка расчета на проверку менеджеру (перевод в `Sent`).
  - **Просмотр:** Детальный просмотр сметы, списка товаров по зонам.
  - **Оплата:** Возможность загрузить платежку или подтвердить оплату (перевод в
    `Payment Review`).

### 2. Менеджер (Manager/Admin)

Сотрудник компании HICS, эксперт-технолог.

- **Дашборд:**
  - Обзор (Exper Overview): Статистика по лидам, активным проектам.
  - Пайплайн (Pipeline): Канбан/Список проектов, разделенный на "Мои" и "Новые
    заявки" (Leads).
  - База знаний (KB): Управление мастер-каталогом товаров (Master Inventory).
- **Работа с проектом:**
  - **Взять в работу:** Присвоение себе "ничейной" заявки (`Assign`).
  - **Экспертиза:** Режим `Expert Mode` для редактирования состава оборудования,
    добавления маржи, стоимости доставки и монтажа.
  - **Выставление счета:** Перевод проекта в статус `Invoice`.
  - **Логистика:** Управление статусами доставки (`Processing`,
    `Sent to Warehouse`, `Shipping`).

## 🔄 Статусная Модель (State Machine)

Система базируется на жесткой машине состояний, описанной в
`CalculationEntity.ts`.

### Полный список статусов:

| Статус                   | Роль                    | Описание                                                | Возможные переходы             |
| :----------------------- | :---------------------- | :------------------------------------------------------ | :----------------------------- |
| **draft** (Черновик)     | 👤 Клиент               | Создан, но не отправлен. Редактируется клиентом.        | `sent`                         |
| **sent** (Отправлен)     | 👤 Клиент → 👔 Менеджер | Клиент отправил заявку. Менеджер видит её в "Новых".    | `expert`, `changes`, `invoice` |
| **expert** (Экспертиза)  | 👔 Менеджер             | Менеджер взял в работу, проводит аудит и вносит правки. | `changes`, `invoice`           |
| **changes** (Правки)     | 👤 Клиент ↔ 👔 Менеджер | Запрос уточнений у клиента. Клиент может редактировать. | `revision`, `sent`             |
| **revision** (Проверка)  | 👤 Клиент → 👔 Менеджер | Клиент внес правки и вернул менеджеру.                  | `expert`, `invoice`            |
| **invoice** (Счет)       | 👔 Менеджер             | Финальное согласование, выставлен счет.                 | `payment_review`, `changes`    |
| **payment_review**       | 👤 Клиент → 👔 Менеджер | Клиент "Оплатил". Менеджер проверяет поступление денег. | `paid`, `changes`, `invoice`   |
| **paid** (Оплачен)       | 👔 Менеджер             | Деньги поступили. Проект переходит в производство.      | `processing`                   |
| **processing**           | 👔 Менеджер             | Комплектация заказа.                                    | `sent_to_warehouse`            |
| **sent_to_warehouse**    | 👔 Менеджер             | Отправлено на склад.                                    | `ready`                        |
| **ready** (Готов)        | 👔 Менеджер             | Готов к отгрузке.                                       | `shipping`                     |
| **shipping** (В пути)    | 👔 Менеджер             | Доставка клиенту (курьер/ТК).                           | `completed`                    |
| **completed** (Выполнен) | 👔 Менеджер             | Успешное завершение.                                    | `closed`                       |
| **closed** (Закрыт)      | Система                 | Архив.                                                  | _Нет переходов_                |

## 🛠 Технические Особенности

1. **Синхронизация (Real-time):**
   - Используется `GlobalChatHub` и `chatService` для получения сигналов о новых
     сообщениях и изменениях статусов.
   - Менеджер видит обновления "на лету" (React Query Invalidation).
   - Клиент получает уведомления (Toast + обновление списка).

2. **Валидация и Безопасность:**
   - Статусы защищены на уровне домена (`canTransitionTo`).
   - Менеджер не может редактировать "чужие" проекты без присвоения.
   - Клиент не может менять ничего после ухода из `draft`/`changes`.

3. **Архитектура:**
   - **Frontend:** React, TypeScript, Vite, Tailwind.
   - **State:** React Query (Server State) + Local State.
   - **Backend:** Supabase (Database, Auth, Realtime) + Vercel Serverless
     (Email).

## 🚀 Потенциал для развития (Что можно внедрить)

На основе анализа, вот зоны для роста:

1. **Документооборот (PDF):**
   - Авто-генерация КП (Коммерческого предложения) в PDF.
   - Авто-генерация Счета на оплату.
2. **История изменений (Audit Log):**
   - Кто и когда поменял статус?
   - Что именно изменил эксперт в смете? (Версионность).
3. **Интеграции:**
   - 1С / МойСклад (для актуализации цен и остатков в `Master Inventory`).
   - Telegram Bot (уведомления менеджерам о новых заявках).
4. **Складской модуль:**
   - Сейчас логистика "линейная" (статусы). Можно добавить реальное списание
     остатков.
